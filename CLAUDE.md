# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`@hoyasumii/linkedin` — an unofficial MCP server (stdio only) and TypeScript SDK to create, edit and delete the
signed-in member's own LinkedIn posts, over LinkedIn's official API. The SDK is generated by orval from our own
OpenAPI spec. Unlike its siblings `@hoyasumii/libretranslate` (`../libretranslate`), `@hoyasumii/signoz` and
`@hoyasumii/plane`, the CLI exposes no tools as commands: it only signs in (`linkedin mcp config [--web]`) and
registers the server in AI clients (`linkedin mcp install`). Node >= 20, CommonJS through `tsc`, pnpm. Windows
support included.

**What LinkedIn allows.** A member's own app gets `w_member_social` (Share on LinkedIn) and `openid profile`
(Sign In with LinkedIn using OpenID Connect) self-serve: create, edit (commentary only) and delete posts, and
`userinfo`. Reading posts needs `r_member_social`, closed to new apps (even GET by URN), and the DMA portability
API is EEA/Switzerland only. So the server keeps a local registry of what it posted (`posts.json`) and its "read"
tools read that. Never add scraping, private (Voyager) endpoints or cookie auth. Tokens last 60 days; refresh
tokens only exist for partners LinkedIn enabled. `spec/openapi.yml` describes the API from LinkedIn's public docs
on Microsoft Learn only.

## Common Commands

```bash
pnpm install              # Install dependencies (and the husky hooks)
pnpm build                # tsc → dist/
pnpm test:unit            # Jest unit tests (a fake LinkedIn on node:http; no network)
pnpm test tests/unit/mcp/tools.test.ts   # One file
pnpm test:live            # Posts, edits and deletes on the real LinkedIn, from .env.test (see env.example)
pnpm check:types          # tsc --noEmit over src and tests
pnpm check:lint           # oxlint
pnpm check:format         # oxfmt (120 columns)
pnpm check:knip           # Unused files, exports and dependencies
pnpm codegen              # spec → src/generated/ (orval; never hand-edit)
pnpm docs:dev             # Preview the docs site (append `--locale pt-BR`)
pnpm docs:build           # Build the docs site, every locale, into website/build/
pnpm docs:serve           # Serve website/build/ (where search works; it does not under docs:dev)
GIT_USER=<user> pnpm docs:deploy  # Build and push the site to the gh-pages branch (GitHub Pages)
```

Husky runs lint and format on commit, types, knip and unit tests on push. Commits follow
Conventional Commits (commitlint). Every script must run on Windows too: no `rm`, `$VAR`, `VAR=1 cmd`.
`.github/workflows/cd.yml` (Continuous Delivery) runs on every push to `main`: the same checks and the build, then
`npm publish` (Trusted Publishing, no token) plus a `v<version>` tag and GitHub release when `package.json`'s version
is not on npm yet, and `pnpm docs:deploy` to `gh-pages` when the push touches `website/` or `src/`. To release, bump
`version` and merge to `main`.

## Architecture

**SDK** (`src/`). `orval.config.ts` reads `spec/openapi.yml` (OpenAPI 3.1; `/rest/videos?action=…` paths keep the
two video POSTs apart) and writes `src/generated/`: `endpoints.ts` (`client: "fetch"`,
`includeHttpResponseReturnType: false`), `model/` and `zod.ts`. Every generated function sends through the mutator
`customFetch` (`src/transport.ts`): it asks the `AccessTokenSource` (a string or a function, called per request),
sends the token only to LinkedIn's hosts or the configured origin (`sendsTokenTo`), adds `LinkedIn-Version` and
`X-Restli-Protocol-Version: 2.0.0` on `/rest/`, turns a 201 with an empty body into `{ id }` from `x-restli-id`,
throws `LinkedInAuthError` on 401 and `LinkedInApiError` otherwise (`src/errors.ts`, token masked). `uploadBytes`
PUTs media and answers the ETag. `createLinkedInClient` (`src/client.ts`) encodes URNs in paths, sets
`X-RestLi-Method` (PARTIAL_UPDATE, DELETE), escapes text with `toLittle` (`src/little.ts`: every reserved
character, `#word` kept as a hashtag, 3000 characters after escaping), uploads images/documents/videos
(`src/media.ts`: checks, polling until AVAILABLE; a 403 on the status read means "retry the create while it says
the media is processing"), and resolves the author from `userinfo` once. `src/posts.ts` parses post URNs/URLs
(activity links are refused with the "Embed this post" hint). `src/registry.ts` is `PostRegistry` (`posts.json`,
re-read on every call). `src/auth/oauth.ts` (authorization URL, code exchange, refresh) and
`src/auth/credentials.ts` (`credentials.json`, 0600, `credentialSource` re-reads it per call and refreshes when a
refresh token and the app are at hand).

**MCP server** (`src/mcp/`, the `@hoyasumii/linkedin/mcp` subpath, stdio only). `config.ts` resolves env > saved
`.env` > default (`LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET`, `LINKEDIN_REDIRECT_PORT` default 3769,
`LINKEDIN_API_VERSION` default `202609`; env-only `LINKEDIN_ACCESS_TOKEN`/`LINKEDIN_PERSON_URN`) and
`connectionFor(config)` builds `{ client, registry, credentialsFile }`. `build.ts` registers `tools/posts.ts`
(`linkedin_whoami`, `_create_post`, `_edit_post`, `_delete_post` with `confirm: true`, `_list_posts`,
`_get_post`); `stdio.ts` serves it; `cli.ts` is the `linkedin-mcp` bin (stdout is the protocol, log to stderr).
Tool errors go through `describeError` (`errors.ts`).

**CLI** (`src/cli/`, the `linkedin` bin, citty 0.1.x). `run.ts` dispatches `mcp` and `docs`. `linkedin mcp …`
(`src/cli/mcp/index.ts`): `config` (`--web` page or terminal prompt/flags, then the browser sign-in),
`status` (exit 3 when not signed in), `logout`, `install`/`uninstall`. `config-ui.ts` serves the form and the OAuth
redirect on `localhost:<LINKEDIN_REDIRECT_PORT>` (127.0.0.1 and ::1; URL token + Host check; one-time `state`) and
holds the input rules (a blank secret keeps the saved one); `config-page.ts` renders it. `install.ts`,
`hosts.ts` (WSL→Windows bridge), `picker.ts` and `deps.ts` come from plane (via libretranslate), with the daemon
and boot parts removed; `install` launches `node <dist>/mcp/cli.js` over stdio and needs a sign-in
(`requireSignedIn`).

**Docs site** (`website/`, a pnpm workspace package, plane's site with a LinkedIn-blue accent, #0a66c2):
Docusaurus, published to GitHub Pages at `https://hoyasumii.github.io/linkedin/` by `pnpm docs:deploy`. The guides
are plain Markdown in `website/docs/`, mirrored page for page in
`website/i18n/pt-BR/docusaurus-plugin-content-docs/current/`; change both together (`tests/unit/website.test.ts`).
`website/docs/api/` is generated by docusaurus-plugin-typedoc on the `en` build only, and gitignored.
`llms.txt` and `llms-full.txt` are generated into the build root by docusaurus-plugin-llms; never hand-write them.

## Conventions

- Code, comments and messages in English.
- Avoid `any`; tool inputs are zod schemas, API shapes come from `src/generated/model`.
- Never log the access token or the Client Secret; tool errors go through `describeError` (`src/mcp/errors.ts`).
- The live test posts as the user (CONNECTIONS visibility) and deletes the post: run it only when asked.
